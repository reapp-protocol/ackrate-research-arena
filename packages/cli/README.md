# @ackrate/cli 0.1.8

Run the **ackrate** payment flow from a terminal: scaffold configuration,
create testnet accounts, authorize an AP2 mandate, and make agent-signed
payments through the live MandateRegistry contract on Stellar.

The CLI is intentionally thin. It prepares inputs, signs with the correct
testnet key, and submits transactions; the contract remains the source of truth
for scope, budget, expiry, replay protection, and settlement.

Testnet only. Keys generated by the CLI are disposable testnet burners and must
never be reused on mainnet.

## Install

```bash
npm install --global @ackrate/cli@0.1.8
ackrate --help
```

## Quick start

```bash
ackrate demo research-agent
```

The demo creates three ephemeral testnet accounts, registers a real mandate,
approves the contract allowance, and has an agent buy research sources one at a
time. The mandate covers three payments; a fourth payment is rejected by the
contract. No model API key is required.

## Step-by-step flow

```bash
ackrate init
ackrate setup
ackrate mandate create
ackrate pay
ackrate settlement reconcile
ackrate settlement acknowledge <TX_HASH>
```

Before broadcast, the CLI signs the transaction, derives its exact hash and
validity deadline, and durably stores a private journal under `ACKRATE_HOME`.
Concurrent processes race one atomic claim, so only one can submit. If the RPC
cannot confirm the result, later payments fail closed until the exact hash is
reconciled and acknowledged.

## Commands

| Command | What it does |
|---|---|
| `ackrate init [-f]` | Write `ackrate.config.json` |
| `ackrate setup [-f]` | Generate and fund disposable testnet accounts |
| `ackrate mandate create [-b <xlm>] [-e <seconds>] [-f]` | Register a mandate and approve its SEP-41 allowance |
| `ackrate pay [amount]` | Make an agent-signed contract-enforced payment |
| `ackrate settlement reconcile` | Resolve the exact durable transaction hash |
| `ackrate settlement acknowledge <tx-hash>` | Accept one recorded success and reopen the payment path |
| `ackrate demo research-agent` | Run the complete capped testnet flow |

## How it works

1. The user owns the funds and authorizes the mandate.
2. The agent requests payments by calling the contract.
3. The merchant is the only allowed payee.
4. MandateRegistry validates and transfers funds atomically.

The allowance goes to the contract, never the agent or CLI. A compromised agent
cannot bypass merchant scope, expiry, budget, revocation, or sequence checks.

## Local files

| File | Safe to commit? | Purpose |
|---|---:|---|
| `ackrate.config.json` | Yes | Network, contract ID, explorer, price, and budget |
| `~/.ackrate/credentials.json` | No | Disposable testnet account secrets |
| `~/.ackrate/mandate.json` | No | Active mandate inputs and transaction hashes |
| `~/.ackrate/pending-settlement/state.json` | No | Crash-safe settlement journal |

Set `ACKRATE_HOME` to relocate all private CLI state:

```bash
ACKRATE_HOME=/tmp/ackrate-demo ackrate setup
```
